# 预定事件推进与投递优化

状态：两轮实验与代表性完整模型验证已完成；生产 Network 生命周期接入待细化。当前 NetStim 每步按连接匹配完整时间表，长时间表及连接声明碎片会增加工作。已有 [完整模型基线](../../../../benchmarks/performance/synapse_events/results/netstim-baseline.md) 中，固定窗口内事件数，K 从 10 增至 10000，CPU 完整运行从 12.146 ms 增至 1286.255 ms；GPU 从 105.351 ms 增至 114.304 ms。两种设备不能预设相同收益。

当前 owner 与状态布局见 [Synapse 架构](../current/architecture.md)、[Network 事件](../../network/current/connections.md)。固定版本的外部依据见 [预定事件推进参考](../references/scheduled-event-delivery.md)。

## 从 spike 到 event

A 的 spike 为 `[1.0, 1.2, 5.0] ms`，delay 为 1 ms；B 为 `[2.0, 7.0] ms`，delay 为 0 ms。dt=1 ms 时，到达步分别为 A `[2,2,6]`、B `[2,7]`。第 2 步应输出 A:2、B:1，之后才乘连接权重并投递目标。

全表查询在第 3 步仍匹配五条记录。游标只看尚未消费的位置。紧凑桶直接索引第 3 步的空区间。必须保存事件重数；先相加 spike_time 与 delay 再取整，不能分别量化。

## 第一版：四种查询方式

| 方法 | 准备与运行 | 主要代价 |
| --- | --- | --- |
| current | 实际 NetStim.event_count | 每步完整表匹配；编译器可能折叠固定算术 |
| scan | 同精度预计算到达步，仍全表匹配 | 区分预计算与算法收益 |
| cursor | 每连接一个位置，消费当步所有事件 | 每步查看连接；批量循环受最多重数影响 |
| bucket | 紧凑连接索引数组和时间步 offsets | 准备、排序、传输及分块循环 |

四条路径输出相同的每连接整数计数，之后使用相同权重和目标归约。查询数组作为动态 JIT 参数，避免把整个计数轨迹预录进编译常量；current 保留实际源码对 NetStim 常量时间表的处理。桶每块默认 128，末块 mask，尾部保留一个块避免动态切片起点钳制；比较 32/128/512。不是按最大单步事件数为所有步分配二维数组。

第一版固定 source、dt、delay、拓扑和窗口，改变这些量需要重新准备。权重在运行时读取；游标按连接维护，不混入源端去重优化。支持窗口内起点初始化、连续分段、reset。到达步使用当前设备/精度的生产 JAX 量化表达式，不能用 host float64 偷换边界结果。桶准备阶段会把整数表复制到 host 排序后传回设备，这部分成本单独说明。

多步使用 brainstate.transform.scan/for_loop 并整体 jit；调度动态循环仅处理整数状态，权重与突触动力学位于循环外。第一版检查权重和时间常数梯度；事件时间/delay 梯度不在固定调度合同内。

## 实施阶段与验收

1. 固定参考与语义：reference 提供固定提交、CPU/GPU 分工和例子；测试精度、半步和多重事件。
2. 实验内核与测量：四方法、N/M 分层 sweep、K sweep、活动/扇出/块大小，CPU/GPU 同一输入；验证逐步计数、加权输入和 ExpSyn 轨迹/梯度。
3. 生产接入：依据结果决定候选及选择规则，处理 Network 生命周期、缓存失效、权重变化、完整模型与训练；保留原路径对照。
4. 后续研究：相同来源/到达规则查询共享，在线 spike 生成，连接执行分组、live spike 队列；状态合并必须另行满足模型和可观察性等价。

任务进度由 [Synapse TODO](../TODO.md) 维护。实验接口见 [固定窗口查询](../current/experimental-scheduled-events.md) 与 [直接投递及 Cell 适配器](../current/experimental-scheduled-delivery.md)，运行命令见 [benchmark README](../../../../benchmarks/performance/synapse_events/README.md)。

默认窗口 100 ms、dt=.025 ms、随机种子 7；CPU/GPU 测量独立进程、每方法清理编译缓存，预热 2 次、重复 5 次、同步等待。记录源构建、冷准备（含预处理编译、量化、桶排序与传输）、首次执行、稳态运行及调度数组字节。冷准备与首次执行不可称为纯编译时间。设备 allocator 数据不是内核峰值内存；准备阶段临时完整表及源表仍有 O(CK) 成本。

正确性必须逐步逐连接一致，覆盖空表、静默、同一步重复、耗尽、远未来、零/异质 delay、扇出、半步邻近浮点值、非零窗口、分段与 reset。ExpSyn 采用事件后精确指数衰减的统一消费者，不等同于完整 Cell solver；检查轨迹和权重/tau 解析梯度。新模块测试覆盖率 >90%，JAX >=0.8.0。

性能报告分别给 query 与 query+权重+ExpSyn；不相加为百分比。一次使用成本为源构建+准备+首次执行；重用计划需计入首次成本再加后续运行。无稳定加速也是有效实验结果，不自动改默认生产路径。

## 第一版证据与下一阶段建议

[实测页](../../../../benchmarks/performance/synapse_events/results/scheduled-event-queries.md) 收录 36 个场景、72 个设备 worker、四方法共 576 条计时记录，输入及逐步计数的 36 组 CPU/GPU 配对全部通过。N/M、K、活动分布、fanout、delay 和块大小覆盖均已运行。

| 场景（100 ms 窗口） | CPU current / bucket | GPU current / bucket |
| --- | ---: | ---: |
| N=1、M=10、K=10 | 3.191 / 4.356 ms | 45.309 / 151.139 ms |
| N=100、M=100、K=10 | 176.602 / 64.535 ms | 37.716 / 202.123 ms |
| N=10、M=10、K=10000，1000 次到达 | 1192.222 / 5.631 ms | 44.765 / 157.538 ms |

上表为查询、乘权归约和 ExpSyn 消费者的稳态运行，均为 independent 布局。CPU 长表分桶约 212 倍的稳态收益不能解释为完整 Cell 加速：该场景首次使用总成本 current 约 2.589 s、bucket 约 2.451 s；重用 100 次则约 120.619 s 与 3.009 s。桶的准备成本必须计入。

GPU 长表 scan 的稳态 39.198 ms 略低于 current 的 44.765 ms，但冷准备较贵，按当前中位数估算约需 159 次重用才抵消初始成本。当前矩阵的 GPU 最小中位数全部属于 current 或 scan。块大小从 32 增至 512 能降低 GPU burst 分桶时间，但仍未胜过扫描；这只评价本次 JAX 分块 while 执行方式，不能据此否定 Arbor 的紧凑区间布局或其他 GPU 执行内核。

建议下一阶段先设计 CPU 可选的紧凑事件计划，保留短表/小模型的扫描路径；不按“CPU 一律分桶”建立自动规则。GPU 继续保留扫描对照，另行研究把桶内事件并行投递的实现。第一版没有增加生产后端选项。

## 第二轮：三小时内的直接投递实验

第一轮桶查询仍生成长度 C 的连接计数，再乘权归约；当 10 万条连接只有 3 条到期时，这个中间向量可能掩盖稀疏查询收益。第二轮分别寻找 CPU/GPU 的优势组合，准备和编译成本计入首次使用，不预设统一后端。

| 候选 | 到期记录如何变成目标输入 | 约束与代价 |
| --- | --- | --- |
| current / scan / bucket | 第一轮查询后乘权、scatter | 本轮重新测量，保留生产常量处理方式 |
| direct | 相同到达步、连接压缩为整数重数；紧凑桶按块读取当前权重，直接归约到目标 | 动态循环，避免连接计数向量；一阶反向采用显式权重梯度 |
| padded | 同一压缩记录按时间步排成固定宽度矩阵，mask 后并行乘权归约 | 调度数组最多 256 MiB，填充最多为有效记录的 8 倍；超限标为不适用，全空窗口单独处理 |

权重每次执行读取，source、delay、dt、目标和窗口固定；沿用先加时间与 delay 再量化的语义及第一版窗口限制。生产预定事件由 Cell 输入准备阶段的查询与归约消费；Network 中现有 brainevent 路由主要用于 live spike，不能把切换该后端当作 NetStim 查询优化。完整模型通过实验 Cell 子类替换预定事件输入计算，保留 Network 的积分、记录、时间推进及生产默认值。

以下记录第二轮已经执行的历史协议，不作为后续实验的默认轮数或授权。该轮核心矩阵固定 100 ms、dt=.025 ms、float32、种子 7：小规模 1/10/10、大规模 100/100/10、长表 10/10/10000，以及 10/100 下 sparse、burst、dense。五方法在 CPU/GPU 初筛，预热 2 次、计时 5 次；各场景的胜出候选与基线增加两个独立进程复测，每个 worker 限时 120 秒。三次独立运行均更快且总体中位数改善至少 10% 才推荐为稳定优势，否则标记持平、轻微优势或退化。

完整模型验收小规模、大规模、长表的独立布局及大规模共享布局；逐步目标输入、电导和膜电位对照生产路径。单元测试覆盖空桶、多重事件、尾块、冲突目标、异质 delay、半步边界、分段、reset、权重变化及权重/tau 一阶反向梯度，并检查 JAX 0.8.0。GPU profiling 对照 sparse/burst，并针对完整模型已出现收益的 shared/padded 增加一个布局对照；诊断与正式计时分开。

该历史批次的总预算从实施开始计 3 小时：实现与基本验证 60 分钟，设备测量及诊断 50 分钟，完整模型与兼容性 45 分钟，报告 25 分钟。优先保证 direct、正确性及完整模型；时间不足先缩减 padded 和额外 profiling。结果必须列明失败、超时、不适用和未执行。共享查询、专用 GPU 内核、全参数搜索和生产自动选择器留到后续阶段，不以本轮样本宣称设备全局最优。

## 第二轮决定与最终执行顺序

[第二轮结果](../../../../benchmarks/performance/synapse_events/results/scheduled-event-delivery.md) 包含六类 micro、四类真实 Cell/Network、三轮关键候选复测及 GPU trace。直接投递、固定宽度投递和实验适配器已经可调用；生产默认仍由原 Cell/Network 执行。

| 范围 | 建议 | 依据与限制 |
| --- | --- | --- |
| CPU 长表、窗口内少量到达 | 优先试 direct | 完整模型 1208.438 → 11.247 ms，107.44×；首次使用仍约 4.8 s |
| CPU 大规模独立状态 | 本配置 padded 较快，direct 作为紧凑候选保留 | 四层同批次对照配对 1.480× / 1.428×；窗口与存储约束仍需分别评估 |
| CPU 共享状态 | direct 或存储允许时 padded | 完整模型分别 12.22× / 13.30× |
| GPU 共享状态 | 存储允许且重复使用时可选 padded | 完整模型 129.210 → 104.663 ms，1.23×；填充约 1.68 倍 |
| 小模型、GPU 独立状态 | 保留 current，scan 作为对照 | 小模型 direct 退化；GPU large padded 仅 1.04×，long 的 micro scan 收益未在完整模型重现 |

共享状态必须由模型显式声明，不能为了套用此表自动合并独立状态。上述是本矩阵的手动选型建议，不是生产设备自动分派阈值。

后续生产化按以下顺序推进。每批执行前依据 [Benchmark 规范](../../../../benchmarks/AGENTS.md) 明确并确认轮数、预热、计时重复、额外校验及预算；粗略比较只提出一轮，不沿用历史三轮协议。达到确认的上限保存未完成项，不自动增加复测或预算：

1. **固定窗口与手动方法接入。** Network 负责准备窗口和运行起点，Cell 保持目标状态 owner。先明确显式方法选择入口；沿用现有生产默认。定义 source/delay/dt/拓扑变化后重建、权重变化复用、reset 和连续分段行为。验收同一模型一次运行与分段运行的逐步输入/g/V、权重与 tau 一阶反向一致；过期窗口必须明确报错或重建，不能静默漏事件。float32 超大绝对步号需先确定整数时钟或窗口重定位。
2. **有限模型回归与选择依据。** 复用当前 small/large/long/shared 固定矩阵，再增加一个多 CV 主动模型和一个 live/scheduled 混合模型。每个候选单独配对 production，记录冷成本、存储及经确认次数的稳态计时；仅在用户要求细致比较或正式性能评估时提出额外独立复测。只在这些证据覆盖后确定默认是否需要按设备/布局变化；不足时继续显式选择。
3. **按 trace 决定 GPU 内核研究。** 若应用需要独立状态下的桶投递收益，再做一个受限原型，目标是消除桶内主机条件检查和小内核启动。验收整数重数、碰撞目标、尾部、单位与权重梯度，并比较真实模型和首次成本；不稳定胜过扫描则停止该方向。源端共享查询单独立项，避免同时改变查询次数、投递布局和状态模型而无法归因。

第一项的生命周期合同尚待讨论，第二、三项依赖它或具体应用需求；此处给出顺序与可观察验收条件，不把它们计为本轮已实现内容。

## 生产接入前的待决定事项

- 怎样根据事件密度、表长度、准备窗口及重用次数选择执行方式？本矩阵不足以定义通用阈值。
- 哪些运行场景值得承担 direct/padded 的准备和存储成本？第二轮已证明直接投递可以避免连接计数中间向量，仍缺面向实际应用的重用分布。
- 窗口怎样从 Network.run/prepare_run 获得，如何续建、reset，以及何时使 source/delay/dt 缓存失效？
- float32 超过 2**20 的绝对步号会触发生产半步 snapping 的分辨率问题，第一版拒绝该窗口；生产接入前需决定整数时钟或窗口重定位并验收长时间运行。
- 如何保持跨窗口 BPTT、记录与 TrainableManager 生命周期？第二轮已通过真实 Network 固定窗口下的权重/tau 一阶反向与运行时权重变化，跨窗口和自动重建仍未验收。

第一轮数值与软件验证：CPU 16 个测试、49 个子场景；GPU 8 个核心测试、40 个子场景；JAX 0.8.0 上全部 16 个测试通过。新代码语句与分支综合覆盖率约 98.8%。两项新增边界测试先复现再修复：dense 末尾事件越出量化窗口，以及大 float32 绝对步号未拒绝。测量版本与局部补测记录见实测页。

第二轮验证：新增 19 个测试、39 个子场景，GPU 10 个核心测试，JAX 0.8.0 上全部 19 个新增测试通过；新增模块综合覆盖率 98.66%。四个初始 full worker 超时记录保留，拆分后完成所需候选；范围、误差、成本和诊断限制见 [第二轮结果](../../../../benchmarks/performance/synapse_events/results/scheduled-event-delivery.md)。

## 完整模型四层对照

独立投递微基准的计时不是完整模型中的事件独占时间。以同一批次完整运行区分 A：100 个无突触 cell；B：挂载 10000 个独立 ExpSyn 但无连接；C：保留连接与时间表，将发放整体后移 110 ms；D：正常输入。C/D 对比 production、direct、padded，A/B 只测 production。

该历史实验的配置、三轮执行协议及预算已归入 [四层实测总结](../../../../benchmarks/performance/synapse_events/results/scheduled-event-controls.md)。后续执行次数必须按 [Benchmark 规范](../../../../benchmarks/AGENTS.md) 单独列出并确认，不沿用历史三轮协议。

验收无突触与无连接结构、静默事件数为零、正常到达数和跨设备输入一致，以及候选相对 production 的逐步输入/g/V、reset 可重复性。报告四组总墙钟和每步摊销时间，A→B→C→D 差值仅表示对照条件变化的整体增量；静默常量优化与求解计算图变化不允许被解读为精确阶段占比。旧微基准和历史无突触结果另列，不混入本批次差值。

四层实测见 [完整模型对照](../../../../benchmarks/performance/synapse_events/results/scheduled-event-controls.md)。CPU 正常输入由 474.901 ms 降至 direct 333.335 / padded 320.748 ms，已接近无连接突触组的 322.622 ms；本规模优先保留 padded 与 direct 的手动选择，后续性能定位转向独立状态更新及 point 电流/求解归约。必须保留 10000 个独立状态，不因同参数而自动合并成共享突触；先用同一完整模型的 trace 区分耗时，再决定是否优化计算布局。

GPU 正常输入扫描 143.089 ms、padded 138.341 ms、direct 301.909 ms；padded 配对加速仅约 1.03×，与 CPU 的约 1.48× 不同。沿用扫描默认，padded 仅作固定窗口重复使用的候选；本对照不触发专用 GPU 内核开发。上述固定窗口生产接入、有限主动/混合模型回归、按 trace 决定内核研究的顺序保持；每项仍需独立验收，四层差值不替代 profiler 的内核归因。
